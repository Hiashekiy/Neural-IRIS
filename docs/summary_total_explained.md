# 总表方法与指标说明

这份说明对应 [summary_total.csv](summary_total.csv) 和 [summary_total.txt](summary_total.txt) 里的结果。总表基于测试集 11986 个样本，`group` 表示结果来源分组，`method` 表示具体算法，`single` 和 `batch` 只是运行方式不同，不是不同算法。

## 方法说明

| 方法 | 说明 |
|---|---|
| largest_empty_circle | 几何基线。从中心点出发，找到在障碍物约束下能放下的最大圆，作为最简单的安全区域近似。 |
| rotated_rectangle | 旋转矩形基线。先估计局部障碍分布，再在多个朝向里搜索面积较大的旋转矩形。 |
| heuristic_ellipse_fit | 启发式椭圆基线。先用局部点云主方向估计椭圆朝向，再用射线安全边界裁剪半径，得到一个近似安全的椭圆多边形。 |
| segmentation_polygon_postprocess | 分割后处理基线。先由自由空间和距离变换得到可行区域，再用射线采样把它转成多边形。 |
| direct_polygon_regression | 直接多边形回归基线。用学习模型预测一圈径向半径，再把这些半径拼成凸多边形；如果模型不可用，会退回到平滑后的几何半径。 |
| ours_corridor_net | 你的 Python 版本。用 PyTorch 模型预测走廊相关参数，再通过几何生成安全多边形。 |
| ours_corridor_cpp | 你的 C++ 版本。与 Python 版使用同一类模型思想，但通过 ONNX Runtime 和 C++ 桥接执行，支持 CPU 和 GPU，也支持 batch。 |
| iris | Drake 的 IRIS 基线。以种子点为中心，在障碍约束下扩张出一个凸安全区域。 |
| decomputil | DecompUtil 基线。通过自由空间分解构造安全多边形，属于外部 C++/WSL 方法。 |
| firi | FIRI 基线。通过局部自由空间和几何分解生成凸安全区域，属于外部 C++/WSL 方法。 |

## 指标说明

| 指标 | 含义 | 越大/越小越好 |
|---|---|---|
| valid | 方法是否成功产出一个合法多边形。这里的“合法”通常要求至少 3 个点、面积大于 0、并且是凸多边形。 | 越大越好 |
| center_in | 多边形是否包含中心点。中心点一般是 MPC 或局部规划的起始点，中心在内说明生成的区域对后续规划更有用。 | 越大越好 |
| coll_rate | 碰撞率。当前总表使用的是放松口径：如果多边形和障碍物的重叠面积达到多边形面积的 1% 及以上，就算碰撞。 | 越小越好 |
| coll_area | 碰撞面积占比。它不是单个样本的简单均值，而是所有样本的碰撞面积总和除以所有样本的多边形面积总和。 | 越小越好 |
| norm_area | 归一化面积。对每个样本，用该方法的多边形实际面积除以参考面积，再取平均。参考面积来自 iris、firi、decomputil 里该样本能得到的最大有效面积。 | 通常越大越好，但要结合碰撞率一起看 |
| lat_ms | 平均推理耗时，单位是毫秒。batch 行表示批处理下的单样本平均耗时。 | 越小越好 |

## 这些指标怎么一起看

1. `valid` 先看方法能不能稳定产出多边形。
2. `center_in` 再看产出的区域是否真的把中心包含进来，这对可用性很关键。
3. `coll_rate` 和 `coll_area` 负责约束安全性，越低越好。
4. `norm_area` 反映区域大小，越大通常越不保守，但前提是碰撞不能明显升高。
5. `lat_ms` 反映实时性，越小越适合在线使用。

## 读表建议

- 如果你在看在线 MPC，可优先比较 `valid`、`coll_rate`、`lat_ms`。
- 如果你在看安全走廊质量，可优先比较 `center_in` 和 `norm_area`，同时检查 `coll_rate`。
- `batch` 版本和 `single` 版本是同一算法的不同运行方式。`batch` 只用于真正支持批处理的实现。

## 备注

- `summary_total.csv` 已经把各组结果汇总到一张表里，并且给每一行加了 `group` 列。
- `norm_area` 在总表里是从已生成的 merged 结果回填的，所以不会再出现空值。
